# 上位机通信协议（STM32F103C8T6）

本文档面向**上位机（PC / 树莓派 / 手机等）开发者**，描述如何通过串口与本设备通信。
不涉及单片机内部实现与烧写细节（那些见《开发踩坑与烧写教程.md》）。

---

## 1. 物理层 / 串口参数

| 项目 | 值 |
|---|---|
| 接口 | USART1（开发板上 PA9 = TX，PA10 = RX） |
| 波特率 | **115200** |
| 数据位 | 8 |
| 校验位 | 无（None） |
| 停止位 | 1 |
| 流控 | 无（None） |
| 电平 | TTL 3.3V（需 USB-TTL 转接；**必须与开发板共地**） |

接线：

| USB-TTL / 上位机 | 开发板 |
|---|---|
| TX | PA10（RX） |
| RX | PA9（TX）——**要接收温湿度就必须接** |
| GND | GND（必须） |
| 3V3 | 3V3（若开发板已单独供电则不接） |

---

## 2. 数据帧格式

本协议**没有帧头、帧尾、长度、校验**：

- **下行（上位机 → 设备）**：固定 **1 个字节** = 一条命令。
- **上行（设备 → 上位机）**：**ASCII 文本行**，以 `\r\n` 结束（仅在被请求时发送，见 §4）。

> 上位机每发一个字节都会**立即执行**。由于没有帧同步，建议每条命令之间留 ≥ 20ms 间隔，
> 避免字节粘连。

---

## 3. 命令字节定义（下行）

命令字节**只有低 4 位有效**，高 4 位会被忽略（内部执行 `cmd & 0x0F`）。

| 位 | 掩码 | 外设 | 1 | 0 |
|---|---|---|---|---|
| bit0 | `0x01` | 红灯（PA7） | 点亮 | 熄灭 |
| bit1 | `0x02` | 蓝灯（PA6） | 点亮 | 熄灭 |
| bit2 | `0x04` | 蜂鸣器（PA5） | 响 | 不响 |
| bit3 | `0x08` | 温湿度上报 | **回发一次温湿度** | 不回发 |

约定：

- **上位机侧永远是 1 = 开 / 0 = 关**，与硬件电气极性无关（板上输出为低电平有效，固件内部已做反转）。
- **每个字节都是"全量状态"**：字节里为 0 的位对应的外设会被**关闭**。
  例如先发 `0x03`（红+蓝亮），再发 `0x01`，蓝灯会被熄灭。
- bit3 只表示"本次是否要回发温湿度"，不保持状态，**每发一次就触发一次**。

---

## 4. 上行数据（设备 → 上位机）

设备只在两种情况下发送数据，其余时间**串口保持静默**。

### 4.1 上电启动提示（被动，仅一次）

设备复位后固定发送一行：

```
DHT11 init ok\r\n
```

传感器探测失败时为：

```
DHT11 init fail\r\n
```

> 上位机连接后收到的第一行通常是这句，可据此判断设备是否已就绪。
> 如果没收到，说明设备未上电 / 未复位 / 串口未接通。

### 4.2 温湿度回发（由 bit3 = 1 触发）

发送带 bit3 的命令（如 `0x08`）后，设备读一次 DHT11 并回发一行：

```
T=26,H=59\r\n
```

读取失败（传感器无应答或校验和错误）时回发：

```
T=ERR,H=ERR\r\n
```

字段说明：

| 字段 | 含义 | 单位 | 取值 |
|---|---|---|---|
| `T` | 温度 | ℃ | 整数 `0`~`50`，或字符串 `ERR` |
| `H` | 湿度 | %RH | 整数 `20`~`90`，或字符串 `ERR` |

---

## 5. 上位机解析方法

1. 按 `\n` 切分接收缓冲区（建议同时容忍 `\r\n` 与 `\n`）；
2. 对每一行：
   - 若以 `DHT11 init` 开头 → 设备启动提示，记录状态即可；
   - 否则按 `,` 分成两段，再各按 `=` 取值 → 得到 `T` / `H`；
   - 若值为 `ERR` → 本次读取失败，可稍后重试（间隔 ≥ 1s）。

推荐伪代码：

```
line = 读到的一行（去掉结尾 \r\n）
if line.startswith("DHT11 init"):
    ready = line.endswith("ok")
elif "," in line:
    temp_str, humi_str = line.split(",")          # "T=26" / "H=59"
    temp = temp_str.split("=")[1]                 # "26" 或 "ERR"
    humi = humi_str.split("=")[1]
    if temp == "ERR" or humi == "ERR":
        # 读取失败
    else:
        temp = int(temp); humi = int(humi)
```

> **不要用按固定长度读取**的方式解析：`T=26,H=59` 与 `T=ERR,H=ERR` 长度不同，
> 而且 `init ok` / `init fail` 长度也不同。**必须按行（`\n`）解析**。

---

## 6. 时序约束

| 约束 | 说明 |
|---|---|
| DHT11 采样间隔 | **≥ 1 秒**。两次带 bit3 的命令间隔太短，第二次会回 `T=ERR,H=ERR` |
| 建议最小间隔 | 上位机轮询温湿度建议 **2s 一次**，留足余量 |
| 命令间隔 | 相邻两个命令字节建议 ≥ 20ms |
| 响应延迟 | bit3 命令发出到收到 `T=..` 约 **25~30ms**（读传感器耗时），建议读超时设为 ≥ 500ms |
| 无心跳 | 设备不会主动上报。需要心跳时上位机需自己发命令（如 `0x00`）并等待回显，或定时发 `0x08` 读温湿度 |

---

## 7. 命令速查表

| 发送值 | 效果 | 是否回发温湿度 |
|---|---|---|
| `0x00` | 全部关闭 | 否 |
| `0x01` | 红灯亮 | 否 |
| `0x02` | 蓝灯亮 | 否 |
| `0x04` | 蜂鸣器响 | 否 |
| `0x07` | 红灯 + 蓝灯 + 蜂鸣器 全开 | 否 |
| `0x08` | 全部关闭 | **是** |
| `0x09` | 红灯亮 | **是** |
| `0x0A` | 蓝灯亮 | **是** |
| `0x0F` | 三个全开 | **是** |

> 表里为 1 的位对应外设开，其余位对应外设一律关。

## 8. 典型交互流程

```
上位机                                设备
  |                                     |
  | （设备上电 / 复位）                  |
  |  <---------- "DHT11 init ok\r\n"    |   收到即视为就绪
  |                                     |
  |  ---- 0x09 (红灯亮 + 请求温湿度) -->  |
  |  <---------- "T=26,H=59\r\n"        |   红灯亮，同时拿到温湿度
  |                                     |
  |  ---- 0x08 (全关 + 请求温湿度) ---->  |
  |  <---------- "T=26,H=59\r\n"        |   红灯灭，再读一次
  |                                     |
  |  ---- 0x00 (全关，不请求) --------->  |   无任何回发
```

## 9. 示例代码（Python + pyserial）

```python
import serial
import time

ser = serial.Serial(
    port="/dev/cu.usbserial-110",   # Windows: COMx
    baudrate=115200,
    bytesize=8,
    parity=serial.PARITY_NONE,
    stopbits=1,
    timeout=0.5,
)

def send(cmd: int) -> None:
    """下发一个命令字节（只发低 4 位有效）"""
    ser.write(bytes([cmd & 0x0F]))
    time.sleep(0.02)

def read_line():
    """读一行上行数据（以 \\n 结束），超时返回 None"""
    line = ser.readline()
    if not line:
        return None
    return line.decode("ascii", errors="ignore").strip()

# 1) 等待启动提示
while True:
    line = read_line()
    if line and line.startswith("DHT11 init"):
        print("设备就绪:", line)
        break

# 2) 红灯亮 + 请求温湿度
send(0x09)
print(read_line())        # 形如 T=26,H=59

# 3) 定时轮询温湿度（2s 一次，满足 DHT11 的最小间隔）
send(0x08)                # 三路全关
while True:
    line = read_line()
    if line is None:
        continue
    # 解析
    temp_s, humi_s = line.split(",")
    temp = temp_s.split("=")[1]
    humi = humi_s.split("=")[1]
    print("温度:", temp, "℃  湿度:", humi, "%RH")
    time.sleep(2)
    send(0x08)            # 再次请求
```

---

## 10. 注意事项

1. **所有下行命令都是"全量设置"**，不是"切换"。想保持某灯亮着，就要在后续每条命令里都带上对应的位。
2. **bit3 是单次触发**，不会持续上报；需要持续数据就定时发。
3. 收到 `T=ERR,H=ERR` 属正常现象（传感器忙 / 间隔太短 / 接触不良），重试即可，不要视为通信故障。
4. 设备**不会主动发数据**，所以上位机读取时必须设**超时**，否则会一直阻塞。
5. 每次设备复位会额外发一行 `DHT11 init ...`，解析时要能容忍这类非数据行。
6. 当前协议**无校验、无重传**。若现场干扰大导致丢字节，建议后续升级为带帧头/帧尾+校验的帧协议
   （需同步修改固件）。
